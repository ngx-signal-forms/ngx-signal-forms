# Toolkit API source index

Use this index to locate exports and contracts, not as a cached declaration file.
Check the consumer's installed version before choosing an API. Follow the
[source policy](sources.md): main-branch links are latest mutable references,
not installed-version guarantees. The guidance baseline is Angular 22.1;
inspect actual peers and declarations rather than assuming a patch version.

## Export authority

For an installed package, read its `package.json` exports map and follow the
selected entry's `types` target to its shipped declarations. Source can contain
`@internal` members stripped from those declarations. Do not use source-only
methods to make a consumer example compile.

For deeper source lookup, start from these online public barrels, then follow
the symbol to its declaration and JSDoc. These are not required local files:

from published exports. The root source index above, not the `/core` barrel,
defines the consumer root API. Use `provideErrorMessages()` and
`provideFieldLabels()`, not the internal registry tokens.

## Task contracts

Read the linked contract before composing the named APIs.

| Work                                                        | Contract and source                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native form, schema, custom control, or submission action   | [Bundled Angular reference](signal-forms.md). Follow installed Angular's exports to its declarations, including referenced type chunks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Config, appearance, orientation, markers, semantics presets | [Core](../core/guide.md), [form-field](../form-field/guide.md); deeper [per-setting cascades](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/docs/BEST_PRACTICES.md#1-configure-at-the-highest-tier-thats-true), [theming](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/form-field/THEMING.md), and [control families](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/docs/CUSTOM_CONTROLS.md#field-shaped-vs-widget-shaped-custom-controls).                                                                                           |
| Warning timing, message resolution, or submission helpers   | [Warning contract](../core/guide.md#warning-helpers); deeper [warnings doc](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/docs/WARNINGS_SUPPORT.md). `warn:` still makes Angular invalid. Warning-aware submission gates blockers before bypassing Angular validation and does not wait for pending checks.                                                                                                                                                                                                                                                                               |
| Low-level visibility factories                              | [Composition reference](headless-composition.md#visibility-and-aggregation). Direct `createShowErrorsComputed()` calls need explicit submitted status for `on-submit`; low-level visibility helpers accept `configDefault` rather than injecting provider configuration themselves.                                                                                                                                                                                                                                                                                                                        |
| Identity or third-party wrapper DI                          | [Bundled wrapper channels](headless-composition.md#host-composition). Identity shadows registries per channel; `hintIds: null` falls back, `[]` is authoritative. Provider bound-null and unbound states have no control-ID fallback. Identity writers remain internal.                                                                                                                                                                                                                                                                                                                                    |
| Manual ARIA or CSS-hidden controls                          | [Visibility contract](headless-composition.md#control-visibility). Probe the actual `aria-invalid` carrier, not just the wrapper. [Browser evidence](../testing/guide.md#browser-state-checks) distinguishes one hidden radio from a hidden group.                                                                                                                                                                                                                                                                                                                                                         |
| Programmatic errors or grouped state                        | [Bundled headless contracts](headless-composition.md#visibility-and-aggregation). `createErrorState()` returns raw errors; render resolved copy. Aggregation factories are pure and take independent, pre-resolved error/warning visibility signals.                                                                                                                                                                                                                                                                                                                                                       |
| Character count                                             | [Headless counter](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/headless/README.md#ngxheadlesscharactercount) requires `maxLength`, as does `createCharacterCount()`. Only the styled counter can infer it from validation metadata. [Assistive docs](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/assistive/README.md) cover CSS thresholds and announcement formatting.                                                                                                                                                            |
| Vest registration or manual run                             | [Bundled Vest guide](../vest/guide.md); deeper [suite input](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/vest/README.md#validatevest), [manual settlement](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/vest/README.md#awaiting-a-manual-runs-outcome), [lifecycle and SSR](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/packages/toolkit/vest/README.md#suite-lifecycle). The bound path value is the suite input; await `settled()`, not a superseded `runResult`. Isolate suites and adapters per SSR request. |
| Accessibility assertions                                    | [Testing guide](../testing/guide.md). `runOnly` cannot override the WCAG baseline. Custom tag subsets must be valid and nonempty. Axe covers only automatable criteria; keep keyboard, focus, theme, and live-region evidence.                                                                                                                                                                                                                                                                                                                                                                             |
| Removed symbols or renamed appearances                      | [Pitfalls](pitfalls.md#removed--non-public-apis--never-use) and [migration workflow](../migrations/guide.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Renderer contracts

Read the bundled [renderer contract](headless-composition.md#renderer-overrides).
It covers both callers, their different input sets, the fieldset's pre-filtered
errors, nullable names, stable alert/status containers, and the hint's host-owned
ID. A shared renderer must accept both callers. Per-message IDs do not replace
container IDs. For full provider examples, use the deeper
[renderer interface](https://github.com/ngx-signal-forms/ngx-signal-forms/blob/main/docs/CUSTOM_WRAPPERS.md#the-renderer-interface).
