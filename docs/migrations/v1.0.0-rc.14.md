# Migration to v1.0.0-rc.14

## Upgrade from v1.0.0-rc.13

Scope: the RC.13-to-RC.14 upgrade. This release contains one additive fix.
No consumer migration is needed.

No public TypeScript export is removed or renamed. No runtime behavior, peer
dependency range, or engine range changed in this hop.

### Upgrade checklist and compatibility

- [ ] Confirm the installed toolkit version is RC.13. For earlier versions,
      first follow the [migration index](./README.md).
- [ ] Select `1.0.0-rc.14` in your package manager. Update the dependency and
      lockfile together.
- [ ] Keep compatible peers. Angular common/core/forms remain
      `>=22.0.0 <23.0.0`; optional Vest remains `>=6.0.0 <7.0.0`, and optional
      axe-core remains `>=4.5.0`. See [compatibility](../../COMPATIBILITY.md)
      and the [package manifest](../../packages/toolkit/package.json).
- [ ] Build and run your existing type-check and tests. No code change is
      required.

### Required changes

None.

### Additions and compatibility

- `NgxFieldIdentityProvider` is now also exported from the
  `@ngx-signal-forms/toolkit/form-field` secondary entry point. The root
  `@ngx-signal-forms/toolkit` export is unchanged. Third-party wrappers that
  import everything else from `form-field` can now import the host directive
  from the same entry point:

  ```typescript
  // Before (still works)
  import { NgxFieldIdentityProvider } from '@ngx-signal-forms/toolkit';

  // After (optional)
  import { NgxFieldIdentityProvider } from '@ngx-signal-forms/toolkit/form-field';
  ```

  See [ADR 0011](../decisions/0011-field-identity-provider-host-directive.md)
  for the host directive itself.
