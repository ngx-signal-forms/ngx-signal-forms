## Discrepancy spotted in the primary source (not in the article)

The `pr` skill's own `CREDITS.md` prose links `show-me` to `github.com/humanlayer/humanlayer`, but the `SKILL.md` front-matter metadata links the same credit to `github.com/humanlayer/skills/blob/main/plugins/show-me/skills/show-me/SKILL.md`. The second URL is the one that resolves to actual skill content; treat it as the correct reference if reusing the attribution.

## Context not independently re-verified

The article's framing of _why_ to prefer `/implement-spec` vs. a "deterministic loop" script (e.g. the author's own [Sandcastle](https://github.com/mattpocock/sandcastle) project) is the author's stated opinion, not a spec-level claim — it is reported as his recommendation, not verified against a separate source.

## Applicability to ngx-signal-forms

The repository does not declare an installation of `mattpocock/skills`; its
documented skills.sh command installs this repository's own `ngx-signal-forms`
skill. The maintainer chose to adopt the glossary filename, while keeping the
project's existing ADR location and PR checklist.

1. **Applied: rename the domain document.** `CONTEXT.md` is now `GLOSSARY.md`.
   The domain terms were separated from implementation details, which now live
   in [`docs/agents/domain-invariants.md`](../agents/domain-invariants.md).
   Active references and contributor guidance were updated. There was no
   `CONTEXT-MAP.md` to rename.
2. **Keep `/implement-spec` optional.** It may help
   when one spec has a dependency graph with independent tickets, but first
   reconcile its integration-branch/worktree behavior with this repository's
   issue-start and sandbox rules. Do not make it the default for ordinary
   single-ticket work.
3. **Applied: align the PR template with `/pr`.** The template now uses
   `/pr`'s exact `Summary`, `Evidence`, and `Merge Danger` headings and prompts
   for its visual, before/after evidence, door classification, and blast radius.
   It retains this repository's required checklist and asks for exact command
   results without requiring evidence that does not exist.
4. **Use `/retro` as a human-reviewed improvement loop**, if the skill is
   installed. It could identify stale instructions and missing automated
   checks, but should not change code or guidance without maintainer approval
   or run automatically in CI.
5. **If managing an installation of Matt's skills**, update it to v1.3 and
   remove any old `resolving-merge-conflicts` skill manually if it remains.
   This repository's current skill setup does not show that it has such an
   installation, so this is not a repo-wide update to apply by default.
